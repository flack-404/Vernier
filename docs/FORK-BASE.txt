What was changed, and why each change is safe
---------------------------------------------

src/lib.rs
  - Added `corrections` and `scan` modules, both behind the `corrections` feature.
  - rank_answer / rank_answer_cached / breakdown_answer now route their composite
    through corrected(), which is compiled out entirely without that feature.
  - Added the correction_answer export.
  The four weights, the MiniLM path and the embedded weight blob are untouched.

src/allocator.rs
  - The #[panic_handler] and #[global_allocator] are gated to
    cfg(all(not(test), target_arch = "wasm32")).
  Upstream leaves them ungated, which is why `cargo test` cannot build for the host
  target and upstream's own unit tests have never run. This is upstream's own
  suggested fix, from its README. Compile-time no-op for the wasm32 release build —
  the baseline binary's hash is unchanged by it.

src/bm25.rs
  - Test expectation only. `exact_match_scores_high` asserted `> 0.85`, which is
    unreachable: the score is normalised by the tf-to-infinity ceiling (K1+1), so an
    exact match of N distinct terms scores exactly 0.4 for any N. Corrected to 0.4
    with the arithmetic written out, and a second test added covering repetition.
  The IMPLEMENTATION is deliberately untouched — it is what the network deploys, and
  matching it is what earns rank agreement. #[cfg(test)] code is not compiled into
  the wasm build at all.

Build warnings
--------------

`cargo test` emits warnings that belong to upstream, not to this fork. They are left
in place deliberately — silencing them would mean editing files we want to keep
identical to the baseline, and every edit there is correlation risk:

  unused import / dead_code   run_projection, lcg_f32 and VOCAB_SIZE are only reached
                              in projection mode. Building --features real_weights
                              leaves them unreferenced. Upstream warns identically.

  static_mut_refs             EMBED_BUF and BREAKDOWN_BUF are upstream's static output
                              buffers, returned to the host by offset. This is the
                              module's ABI, not an oversight, and changing it would
                              break every existing host.

CORRECTION_BUF raises the same static_mut_refs warning for the same reason and by
deliberate symmetry with the buffers it sits alongside.

Verifying this rather than trusting it
--------------------------------------

  make wasm
  tg-score verify -c data/corpus-smoke.json \
      -baseline build/baseline.wasm \
      -upstream <path to upstream telegraph_scoring.wasm> \
      build/vernier.wasm

Section [A] scores every corpus row through both binaries and compares raw float32
bits. Result at the time of writing: 306/306 identical.

Note the fork's binary is NOT byte-identical to upstream's — renaming the crate
permutes the WASM type section, same size, same types, different order — so the
claim under test is behavioural identity on real inputs, which is what matters.
